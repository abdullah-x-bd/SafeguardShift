# SafeguardShift V2 amendments

## 2026-08-11 — Validation-regime amendment before canonical collection

**Timing:** before any V2 canonical agent trajectory was collected and before any V2 primary outcome was observed.

**Original plan:** require two independent human domain/institutional reviewers for every base task before paid canonical collection.

**Reason for amendment:** the study cannot obtain the required external human-review panel. Fabricating, self-authoring, or model-generating records labeled as human expert approval would invalidate the provenance of the study.

**Replacement:** the human gate was replaced prospectively with a synthetic construct-validation regime consisting of deterministic structural checks, executable oracle checks, blinded model-based construct assessment, and balanced deliberate corruption controls.

**Claim-boundary change:** V2 is explicitly framed as a controlled synthetic benchmark. The study will not claim external expert certification, ecological validity, or real-world domain doctrine. Its primary causal claims concern behavior inside the frozen synthetic institutional-safeguard environment.

**Unchanged:** the 72-task 6×6×2 design, five conditions, action contracts, hypotheses, primary metrics, four-model backbone, three backbone replicates, frontier diagnostic subset, provider policy, and V1 archive remain unchanged except where separately documented in the freeze manifest.

**Canonical data status at amendment:** 0 V2 canonical trajectories.

## 2026-08-11 — Construct-validation output serialization repair

**Timing:** before any V2 canonical agent trajectory was collected and before any V2 primary outcome was observed.

**First validation attempt:** the first construct-validation execution completed all planned canonical task-judge calls but encountered widespread invalid validator responses because the forced tool schema used seven long criterion names plus a free-text reason under a small output cap. The run then reached its cost gate during corruption controls.

**Scientific treatment:** the first validation attempt is classified as a technical validation pilot and is not used as evidence that any task passed or failed construct validation. Its raw artifact is retained in GitHub Actions provenance.

**Repair:** the seven validation criteria, 72 tasks, 12 corruption controls and benchmark construct remain unchanged. Only response serialization is compacted to Boolean keys `c1` through `c7` plus numeric confidence `cf`, and the free-text reason is removed.

**Canonical data status at repair:** 0 V2 canonical trajectories.

## 2026-08-11 — Validator qualification and final two-judge unanimity panel

**Timing:** before any V2 canonical agent trajectory was collected and before any V2 primary outcome was observed.

The compact validation execution showed that model validators differ sharply in their ability to detect deliberately corrupted benchmark specifications. Rather than weaken the corruption-control rule or select judges using their opinions about the 72 canonical tasks, validator selection was moved to a control-only qualification stage.

**Prospective qualification rule:** a candidate must return 12/12 valid structured control responses and detect at least 8/12 deliberately corrupted specifications. Candidate selection may use only these corruption controls, never canonical agent outcomes or the 72 real task judgments.

**Qualification results:**

- GPT-5.4: 12/12 valid, 12/12 corruptions detected — qualified.
- Claude Sonnet 5: 12/12 valid, 12/12 corruptions detected after a serialization allowance sufficient for its structured response — qualified.
- Gemini 2.5 Flash Lite: 12/12 valid, 4/12 detected — rejected.
- Gemini 2.5 Flash: 12/12 valid, 5/12 detected — rejected.
- Mistral Medium 3.1: 12/12 valid, 4/12 detected — rejected.
- Grok 4.20: 12/12 valid, 4/12 detected — rejected.

The final construct panel therefore contains the **two models that independently passed the pre-existing corruption-control bar**. To avoid relaxing the original two-positive-vote requirement, V2 now requires **unanimity**: both qualified judges must vote yes on all seven criteria for every one of the 72 tasks. Both judges must also reject every one of the 12 deliberate corruptions in the final validation run.

All earlier 72-task validator judgments are discarded. The final panel is rerun from scratch after this amendment and freeze. No judge was chosen because it made the real benchmark tasks appear stronger.

**Budget:** total validation and qualification spend accrued before the final run is $1.65313968. The final two-judge validation is capped at $0.75. The remaining V2 ceilings are $6.00 for the backbone and $3.30 for the frontier diagnostic, producing a maximum planned program ceiling of $11.71 under the user's $12 authorization.

**Canonical data status at qualification freeze:** 0 V2 canonical trajectories.
